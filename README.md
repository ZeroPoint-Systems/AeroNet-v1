# AeroNet

## What is AeroNet?
AeroNet is a research project investigating whether a critical information boundary exists in
decentralised collective state estimation for UAV swarms, and whether that boundary can be
predicted from sensing, communication, geometry and agent-availability parameters, and shifted
by local, information-driven reconfiguration.

## What is the research question?
See [`research/research_question.md`](research/research_question.md) for the frozen statement.
Short form:

> Does a critical information boundary exist in decentralised collective estimation, how does it
> scale with sensing, communication, geometry and agent availability, and can autonomous
> information allocation shift it?

## How is the repository organised?

```text
AeroNet/
├── research/       # the scientific argument and pre-registered plan
├── theory/         # mathematical framework and models
├── simulation/      # the controlled experimental instrument
├── algorithms/      # baseline and AeroNet algorithm implementations
├── experiments/     # experimental campaigns (pilot, main, ablations, ...)
├── hardware/        # physical validation platform
├── analysis/        # turning raw measurements into evidence
├── papers/          # manuscripts
├── competition/     # ISEF / Conrad / WRO specific materials
├── docs/            # software architecture, contracts, testing, reproducibility
└── tests/           # the test suite, mirroring the simulation package
```

See each folder's own README for details, and see `docs/architecture.md` for how the software in `simulation/`, `experiments/` and `analysis/` fits together.

## How do you reproduce the simulation?
1. Create the environment: `conda env create -f environment.yml` (or `pip install -r requirements.txt`).
2. Pick or write a config under `experiments/configs/`, following the fields set out in `experiments/runners/config.py`.
3. Run it: `python -m experiments.runners.run_experiment --config experiments/configs/pilot_001.yaml`.
4. The result is written to `experiments/raw/<experiment_id>/`, with a manifest also copied to `experiments/manifests/`.
5. Validate the codebase itself first: `pytest`, or, if pytest is not installed, `python tests/run_all.py` runs every test that does not need a pytest fixture. See `docs/testing_strategy.md`.

## How do you reproduce the analysis?
1. Every dataset under `experiments/processed/` is derived from `experiments/raw/` via scripts in `analysis/preprocessing/`.
2. Every figure in `papers/` is generated by code in `analysis/visualisation/`, never edited by hand.
3. See `analysis/reproducibility/` for the exact commands to regenerate datasets, figures and tables from a given experiment manifest.
